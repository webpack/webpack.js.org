يقبل webpack ملفات تخصيص مكتوبة بلغات برمجة وصيغ بيانات متعددة، ما يتيح لك اختيار الصيغة الأنسب لمشروعك: JavaScript أو TypeScript أو CoffeeScript، أو ملف بيانات مثل JSON5 أو YAML أو TOML.

## defineConfig

<Badge text="5.108.0+" />

`defineConfig` دالة مساعدة يصدّرها `webpack` لتوفر للمحررات التحقق من الأنواع والإكمال التلقائي لملف التخصيص، من دون الحاجة إلى تعريفات أنواع إضافية. وهي دالة محايدة لا تنفذ أي عمل وقت التشغيل، بل تعيد التخصيص الذي تمرره إليها كما هو؛ لذلك يمكن استخدامها أيضًا في ملفات JavaScript العادية.

**webpack.config.js**

```js
const { defineConfig } = require("webpack");

module.exports = defineConfig({
  mode: "none",
});
```

تقبل الدالة جميع الأشكال التي يستطيع webpack-cli تحميلها: كائن تخصيص واحد، أو مصفوفة تخصيصات (multi-compiler)، أو دالة تعيد أحد هذين الشكلين، أو مصفوفة من هذه الدوال، أو `Promise` يُرجع أيًا منها.

```js
const { defineConfig } = require("webpack");

module.exports = defineConfig((env, argv) => ({
  mode: argv.mode ?? "development",
  // ...
}));
```

## TypeScript

لكتابة تخصيص webpack بلغة [TypeScript](http://www.typescriptlang.org/)، ثبّت أوّلاً الاعتماديات اللازمة، وهي TypeScript وتعريفات الأنواع ذات الصلة من مشروع [DefinitelyTyped](https://definitelytyped.org/):

```bash
npm install --save-dev typescript ts-node @types/node
# وإن كنت تستخدم webpack-dev-server بإصدار أقل من v4.7.0
npm install --save-dev @types/webpack-dev-server
```

ثم ابدأ بكتابة التخصيص:

**webpack.config.ts**

```ts
import path from "node:path";
import { fileURLToPath } from "node:url";

import webpack from "webpack";
// في حال واجهتك أخطاء TypeScript عند تخصيص `devServer`
import "webpack-dev-server";

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

const config: webpack.Configuration = {
  mode: "production",
  entry: "./foo.js",
  output: {
    path: path.resolve(__dirname, "dist"),
    filename: "foo.bundle.js",
  },
};

export default config;
```

**tsconfig.json**

```json
{
  "compilerOptions": {
    "module": "esnext",
    "moduleResolution": "bundler",

    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "resolveJsonModule": true,
    "isolatedModules": true,

    // يتيح لك كتابة `import ... from './file.ts';`
    "rewriteRelativeImportExtensions": true
  }
}
```

يفترض المثال السابق أنّك تستخدم إصدار TypeScript رقم 2.7 أو أحدث، مع تفعيل خياري `esModuleInterop` و `allowSyntheticDefaultImports` في ملف `tsconfig.json`.

ندعم التخصيص بصيغة `CommonJS` و `ESM` معاً.

بدءاً من الإصدار v22.18.0، أصبح Node.js يدعم [إزالة الأنواع (type stripping)](https://nodejs.org/api/typescript.html#type-stripping) بشكل أصلي، ولذلك فإنّ الإعدادات الإضافية الموضّحة أدناه ليست مطلوبة إلا للإصدارات الأقدم.

> لتفعيل تحويل صياغات TypeScript غير القابلة للحذف، التي تحتاج إلى توليد شيفرة JavaScript مثل تصريحات `enum` وخصائص المُعاملات (parameter properties)، استخدم الراية [--experimental-transform-types](https://nodejs.org/api/cli.html#experimental-transform-types).

إذا كنت تستخدم إصداراً أقدم من Node.js لا يدعم صيغة `typescript`، أو أردت ضبط `module` في `compilerOptions` ضمن `tsconfig.json` على `commonjs`، فأمامك ثلاثة حلول لهذه المشكلة:

- تعديل `tsconfig.json`.
- تعديل `tsconfig.json` وإضافة إعدادات خاصة بـ `ts-node`.
- تثبيت `tsconfig-paths`.

**الحلّ الأول**: افتح ملف `tsconfig.json` وابحث عن `compilerOptions`، ثم اضبط `target` على `"ES5"` و `module` على `"CommonJS"` (أو احذف خيار `module` تماماً).

**الحلّ الثاني**: أضِف إعدادات خاصة بـ ts-node.

يمكنك إبقاء `"module": "ESNext"` لـ `tsc`، وإن كنت تستعمل webpack أو أداة بناء أخرى، فاضبط قيمة بديلة لـ ts-node. [توثيق إعداد ts-node](https://typestrong.org/ts-node/docs/imports/)

```json
{
  "compilerOptions": {
    "module": "ESNext"
  },
  "ts-node": {
    "compilerOptions": {
      "module": "CommonJS"
    }
  }
}
```

**الحلّ الثالث**: ثبّت حزمة `tsconfig-paths`:

```bash
npm install --save-dev tsconfig-paths
```

ثم أنشئ تخصيصاً مستقلاً لـ TypeScript مخصّصاً لملفات تخصيص webpack:

**tsconfig-for-webpack-config.json**

```json
{
  "compilerOptions": {
    "module": "commonjs",
    "target": "es5",
    "esModuleInterop": true
  }
}
```

T> يستطيع `ts-node` تحديد ملف `tsconfig.json` المطلوب عبر متغيّر البيئة الذي توفّره `tsconfig-paths`.

ثم اضبط متغيّر البيئة `process.env.TS_NODE_PROJECT` الذي توفّره `tsconfig-paths` على النحو التالي:

**package.json**

```json
{
  "scripts": {
    "build": "cross-env TS_NODE_PROJECT=\"tsconfig-for-webpack-config.json\" webpack"
  }
}
```

W> وردتنا بلاغات بأن `TS_NODE_PROJECT` قد لا يعمل أحياناً ويُظهر الخطأ `"TS_NODE_PROJECT" unrecognized command`. وقد ظهر أنّ تشغيله عبر `cross-env` يحلّ المشكلة. لمزيد من التفاصيل [راجع هذه القضية](https://github.com/webpack/webpack.js.org/issues/2733).

## كوفي سكريبت

بالطريقة نفسها، لاستخدام [CoffeeScript](https://coffeescript.org/)، ثبّت أوّلاً الاعتماديات اللازمة:

```bash
npm install --save-dev coffeescript
```

ثم اكتب التخصيص:

**webpack.config.coffee**

```coffeescript
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import HtmlWebpackPlugin from 'html-webpack-plugin'
import webpack from 'webpack'

__filename = fileURLToPath(import.meta.url)
__dirname = path.dirname(__filename)

config =
  mode: 'production'
  entry: './path/to/my/entry/file.js'
  output:
    path: path.resolve(__dirname, 'dist')
    filename: 'my-first-webpack.bundle.js'
  module:
    rules: [
      {
        test: /\.(js|jsx)$/
        use: 'babel-loader'
      }
    ]
  plugins: [
    new HtmlWebpackPlugin(template: './src/index.html')
  ]

export default config
```

## Babel و JSX

في المثال أدناه، يُستخدم JSX (صياغة JavaScript الخاصة بـ React) مع Babel لإنشاء تخصيص بصيغة JSON يستطيع webpack فهمه.

> بفضل من [Jason Miller](https://twitter.com/_developit)

ثبّت أوّلاً الاعتماديات اللازمة:

```bash
npm install --save-dev babel-register jsxobj babel-preset-es2015
```

**.babelrc**

```json
{
  "presets": ["es2015"]
}
```

**webpack.config.babel.js**

{/* eslint-skip */}

```jsx
import jsxobj from "jsxobj";

// مثال على plugin مستورد
const CustomPlugin = (config) => ({
  ...config,
  name: "custom-plugin",
});

export default (
  <webpack target="web" watch mode="production">
    <entry path="src/index.js" />
    <resolve>
      <alias
        {...{
          react: "preact-compat",
          "react-dom": "preact-compat",
        }}
      />
    </resolve>
    <plugins>
      <CustomPlugin foo="bar" />
    </plugins>
  </webpack>
);
```

W> إن كنت تستخدم Babel في مواضع أخرى وضبطت `modules` على `false`، فستحتاج إما إلى الاحتفاظ بملفَّي `.babelrc` منفصلين، أو استخدام `const jsxobj = require('jsxobj');` و`module.exports` بدلًا من صياغة `import` و`export` الحديثة. والسبب أن Node يدعم كثيرًا من ميزات ES6، لكنه لا يدعم صياغة وحدات ES6 في هذه الحالة.

## صيغ البيانات (JSON5 وYAML وTOML)

<Badge text="webpack-cli v7.1.0+" />

إذا كان تخصيصك يتكون من بيانات ثابتة فقط، بلا دوال أو قراءة من `process.env` أو قيم محسوبة، فيمكنك كتابته كملف بيانات بدلًا من JavaScript. يحلل webpack-cli الامتدادات التالية مباشرة:

| الامتداد        | حزمة المحلل |
| --------------- | ----------- |
| `.json5`        | `json5`     |
| `.yaml`, `.yml` | `js-yaml`   |
| `.toml`         | `toml`      |

لا تأتي حزمة المحلل **مدمجة** مع webpack-cli؛ ثبّت الحزمة المناسبة للصيغة التي اخترتها ضمن اعتماديات التطوير. إذا لم تكن مثبتة، فسيتوقف webpack-cli ويخبرك بالحزمة المطلوبة.

```bash
npm install --save-dev json5
# أو
npm install --save-dev js-yaml
# أو
npm install --save-dev toml
```

مرّر مسار الملف إلى `--config`، أو اختر له اسمًا يتيح اكتشافه بوصفه [ملف التخصيص الافتراضي](/api/cli/#default-configurations)، مثل `webpack.config.json5`:

```bash
npx webpack --config webpack.config.toml
```

**webpack.config.json5**

```json5
{
  // تتيح JSON5 التعليقات والمفاتيح غير المحاطة بعلامات اقتباس والفواصل الختامية
  mode: "production",
  entry: "./src/index.js",
  output: {
    filename: "bundle.js",
  },
}
```

**webpack.config.yaml**

```yaml
mode: production
entry: ./src/index.js
output:
  filename: bundle.js
```

**webpack.config.toml**

```toml
mode = "production"
entry = "./src/index.js"

[output]
filename = "bundle.js"
```

T> هذه الصيغ مخصصة للبيانات المجردة فقط. إذا احتجت إلى تخصيص ديناميكي، مثل التفريع بحسب البيئة أو إنشاء نسخ من الإضافات أو استخدام تخصيص على هيئة دالة، فاستخدم ملف JavaScript أو TypeScript بدلًا منها.
